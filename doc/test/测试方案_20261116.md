## 1. 测试目标

1. **验证设计符合性**：逐条覆盖设计文档第 1～8 章的规则、第 10 章的验收场景，做到“条款有出处、用例有编号”。
2. **验证业务流程与数据正确性**：组织—人员—登录—订单—工单—裁床—扎号—派工—报工—审批—计件—工资—质检—仓储—出货全链路的数据引用、数量守恒、状态迁移、版本递增均正确。
3. **验证多租户隔离**：任何接口、任何角色、任何参数篡改都不能跨厂读取或写入；越权必须被拒绝并留审计。
4. **验证双库与加密正确性**：默认双写 2PC、默认密文读取、`enc:v1` 信封、AAD 绑定、手机号盲索引、密钥轮换、单写降级与补偿恢复、双向互转全部符合第 3 章。
5. **验证敏感数据边界**：默认 `***` 占位、授权查看、明文离线备份的权限、校验、一次性下载与可恢复性。
6. **形成可复用资产**：环境自检脚本、双库对账 SQL、越权用例集、缺陷与回归基线，支撑后续版本迭代。

## 4. 测试策略

### 4.1 分层策略

| 层级 | 目标 | 手段 | 覆盖用例 |
|---|---|---|---|
| L1 接口契约 | 路径、方法、状态码、错误码、字段结构 | `curl` / PowerShell `Invoke-RestMethod`，对照 §5、§8.2 | 全部 API 类用例 |
| L2 业务功能 | 流程正确、数据正确、状态机合法 | UI 操作 + API 交叉验证；每次写操作后查库/查详情 | TC-ORG/PPL/PORT/PROC/PROD/QMS |
| L3 数据一致性 | 双库、加密、盲索引、数量守恒、版本 | 直连 plain/secure 双库对账；`-datatool`；守恒公式断言 | TC-CRY、TC-PROD、TC-QMS |
| L4 安全与越权 | 四层权限、终端、范围、脱敏、审计 | 权限矩阵逐格执行；篡改 token/参数/ID；日志与审计核对 | TC-AUTH、TC-SENS、TC-ISO、TC-SEC |
| L5 故障与恢复 | 2PC、单写降级、HSM 故障、导出失败、恢复 | 受控故障注入（停 HSM 隧道、杀进程、断库、截断文件） | TC-CRY、TC-BAK、TC-ISO |
| L6 端到端 | 真实角色完成一条完整业务链 | 浏览器 + 手机 H5；数据链路贯通 | TC-PROD 的 E2E 用例、§10.1 八步 |

### 4.2 测试方法

- **等价类/边界值**：编码长度、工号流水、数量 0/负数/上限、金额精度 `NUMERIC(20,6)`、`user_limit` 边界、`version` 冲突、验证码 5 次错误、授权码 1～720 分钟。
- **状态迁移**：按 §8.1 状态机逐条验证合法迁移与非法迁移（如 `confirmed` 付款改金额、`won/lost` 线索重开、`standard` 直接改）。
- **权限矩阵**：§5.5 角色 × 字段级可见性基线，逐格验证“可见/不可见/可写/只读”。
- **数据对账**：每个双写场景执行附录 B 的 SQL，比较主键集合、`version`、敏感字段解密值、`phone_hash`。
- **故障注入**：在 prepare/commit、HSM 调用、导出解密、文件写入四个点注入故障，验证“不返回伪成功、不留半成品、不静默降级”。
- **幂等与重放**：报工 `idempotency_key`、命令 `request_hash`、转换任务断点续跑、恢复 `ON CONFLICT DO NOTHING`。

### 4.3 自动化策略

| 资产 | 用途 | 归属 |
|---|---|---|
| `src/e2e-check.ps1` | 现有冒烟脚本（短信登录→体验进入→建人→查重→停用→换线拒绝） | 作为 R1 冒烟基线，扩展为用例文档中的 API 脚本 |

| 权限矩阵脚本 | 角色 × 接口的批量越权探测 | TC-ISO、TC-SEC |
| UI 自动化 | 关键页面（车间/产线/人员/门户/备份） | 建议 Playwright，本轮以前端手工 + API 断言为主 |

### 6.6 双库与加密观测点

| 观测点 | 期望 |
|---|---|
| 密文格式 | `enc:v1:<key_version>:<base64url(nonce‖ciphertext‖tag)>`，正则 `^enc:v1:\d+:[A-Za-z0-9_-]+$` |
| 明文列 | plain 库为业务明文；secure 库同列不得出现明文 |
| `phone_hash` | 两库相同；同厂同号稳定，跨厂不同；base64url 43 字符（32 字节） |
| AAD 绑定 | 密文换厂/换行/换列后解密失败，不得静默返回空值 |
| NULL 与空串 | NULL 仍为 NULL；空串与 NULL 可区分 |
| NUMERIC/DATE | 解密后严格还原类型，日期 `yyyy-MM-dd`，数值非科学计数法 |
| 密钥版本 | 轮换后新写用新版本，旧密文仍可解 |

### 6.7 数据正确性规则（用例断言必须遵守）

| 编号 | 规则 | 断言方式 |
|---|---|---|
| R1 | 引用完整：组织父级、人员归属、单据外键必须存在且同厂 | 查详情/查库，外键 `(tenant_id,id)` 命中 |
| R2 | 分类型编码唯一：车间全厂唯一；产线/班组同父唯一；跨车间/跨父可重 | 构造重码与跨父同码两组数据 |
| R3 | 数量守恒：报工=良品+次品；总检=通过+返工+报废；入库=合格+拒收+让步+待检 | 逐单据断言等式 |
| R4 | 数量边界：`reported<=planned`、`approved<=reported`、`current_qty>=0` | 构造越界请求应 400/409 |
| R5 | 状态合法：只允许 §8.1 列出的迁移；终态不可逆 | 构造非法迁移 |
| R6 | 乐观锁：每次成功写 `version+1`；旧 `version` 提交 409 `VERSION_CONFLICT` | 并发/重放两次提交 |
| R7 | 时间：存 UTC 微秒、单调不回退；换线 `valid_to=effective_at`；新旧归属区间不重叠 | 查库比较时间戳 |
| R8 | 幂等：同 `idempotency_key`/`request_hash` 重复提交不产生第二笔业务数据 | 重放两次，比对行数与金额 |
| R9 | 审计：所有写与敏感查看均写审计，且不含明文敏感值 | 查 `audit_log`/`platform_audit_log` |
| R10 | 角色覆盖：每厂每角色 ≥2 人，同角色可接手，流程步骤不得只有唯一执行人 | D0.3 计数 SQL + 双人操作 |
| R11 | 可恢复：测试数据仅落在测试租户；执行前后基线行数/校验和可核对；恢复后无残留 | D0.9 快照/恢复核对 |

### 6.8 数据快照与恢复（必须执行）

| 阶段 | 动作 | 通过标准 |
|---|---|---|
| R0 基线 | 两库 `pg_dump -Fc` + `baseline.json`（12 张表行数/迁移版本）+ SHA-256 | 备份可 `pg_restore --list`；E11 通过 |
| 执行中 | 只写 5 个测试租户；造数带测试标记 | 共享租户行数不变 |
| 每轮结束 | 按租户逆序清理，或整库恢复基线 | 测试租户为空；共享行数一致 |
| 最终恢复 | 按 D0.9 步骤 4 恢复两库并校验 | 行数/版本一致、测试租户 0 行、冒烟通过 |
| 证据 | `baseline.json`、恢复日志、核对 SQL、冒烟记录、销毁记录 | 测试报告附件齐全 |

> 不得在共享表执行 `TRUNCATE`/无条件 `DELETE`；恢复失败时停止测试、保留现场，按“阻塞”处理。

## 10. 缺陷管理

### 10.1 严重级别

| 级别 | 定义 | 示例 |
|---|---|---|
| S1 致命 | 数据错误/丢失、跨租户泄露、密钥或明文泄露、双库不一致且返回成功 | 他厂数据可见；密文列出现明文；2PC 单库成功仍返回 200 |
| S2 严重 | 主流程不可用、权限控制失效、审计缺失、数量守恒被破坏 | 工人可调 PC API；换线后双主归属；报工可超计划 |
| S3 一般 | 非主流程功能错误、错误码/提示不符、统计偏差 | 重复编码返回 500；门户板块排序错误 |
| S4 轻微 | 文案、样式、易用性问题 | 提示语标点、对齐 |

### 10.2 缺陷单必填字段

用例编号、环境与配置（读写模式/密钥版本）、严重级别、前置数据、复现步骤、输入、实际输出（含 HTTP 状态与错误码）、期望输出、`request_id`、日志片段（脱敏）、截图/录屏、影响范围。

### 10.3 回归规则

- S1/S2 修复后必须回归关联用例 + 同模块 P0 用例 + 一条双库对账。
- 涉及加密/双写/审计的修复，追加 TC-CRY 对应对账与 TC-SEC 日志检查。

## 11. 风险与应对

| 编号 | 风险 | 影响 | 应对 |
|---|---|---|---|
| RK1 | HSM 服务/隧道不可用 | 所有加密写入与解密读取失败，阻塞 R2/R3 | 提前演练 `ssh -N -L 8443:127.0.0.1:8443`；备用已开通租户；故障场景本身作为 TC-CRY-011 用例 |
| RK2 | 双库环境为共享/远程库 | 测试数据互相污染、迁移版本不一致 | 专用租户前缀 `YZWS00x`；用例只操作本租户；每日校验 E3/E7 |
| RK3 | 2PC 需 `max_prepared_transactions>0` | 双写退化为普通双提交，无法验证原子性 | 环境检查 E4 纳入准入；否则 R3 双写故障用例标记阻塞 |

| RK5 | 短信/微信为演示模式 | 真实验证码、真实扫码不可测 | 验证业务语义与失败分支；真实通道另立专项 |
| RK6 | 实现与设计存在差异（附录 C） | 用例按设计断言会失败，产生噪声 | 差异先评审定性：缺陷或设计变更；用例备注标注当前实现行为 |
| RK7 | 明文备份包含完整敏感信息 | 测试机/截图泄露 | 只在受控目录生成，测试后按保留策略销毁；截图打码；禁止上传共享盘 |
| RK8 | 前端缓存/浏览器存储残留 token | 误判登录态、串号 | 每轮清理 localStorage/Cookie；用例显式检查 |
| RK9 | 断言依赖浮点金额 | 误报 | 统一按 `NUMERIC(20,6)` 字符串/定点比较 |
| RK10 | 多厂/多角色造数污染共享数据 | 影响其他项目/环境不可恢复 | 仅写 5 个测试租户；R0 快照 + D0.9 恢复；每轮核对共享表行数 |
