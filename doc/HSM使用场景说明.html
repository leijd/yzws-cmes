YZWS-MES HSM 使用场景说明

版本 v1.0（2026-11-11） · 代码基线：src/（迁移 001–061） · 密钥提供方：crypto.kms_provider=softhsm2（远程 hsm-sign-service / 本地 PKCS#11 双模式）
阅读说明：本文以当前代码为准描述 HSM 的真实使用方式，并用时序图逐场景展开。 状态标记：✅ 已实现 代码可查可用； 🔶 部分实现 能力已实现但主流程尚未全部切换，文中注明差距； 📋 规划/运维流程 代码未实现，仅存在设计口径或运维脚本约定。 文中“远程模式”指 crypto.softhsm2.server_url 非空时经 HTTP 调用 hsm-sign-service； “本地模式”指后端进程直接经 PKCS#11 加载 SoftHSM2 模块（需 Linux + -tags softhsm2 构建）。

1. HSM 在项目中的位置

项目采用信封加密：每个制衣厂（租户）在 HSM 中持有独立的 RSA-3072 密钥对，私钥不可导出； 业务数据不直接用 RSA 加密，而是由 HSM 密钥对保护每厂随机的 DEK（数据加密密钥）与盲索引密钥， 敏感字段由 DEK 做 AES-256-GCM 字段级加密，密文以 enc:v1:… 信封存入密文库 yzws-v1-sec。 数据库只保存包装后的密钥密文与 key_wrap_ref 引用，永不保存私钥、PIN、API Key 或明文密钥。

图 1　HSM 总体架构：统一 KeyProvider 契约 + 每厂独立密钥 + 双库信封加密
两库读取口径（重要）：默认 read_source=secure，业务读取一律走主库 yzws-v1-sec（唯一性校验、登录查询、列表检索等均是）； yzws-v1 仅作为双写明文副本，测试期主要用于对账与核查加密库数据正确性（比对两库数据、排查异常），日常不作为业务读取来源。 密钥记录 tenant_crypto_key 与备份任务元数据 backup_job 均双写两库，运行期一律从主库读取（明文库仅对账）；存量历史记录主库缺失时按明文库兜底一次。

1.1 密钥体系

密钥生成位置存储位置用途
租户 RSA-3072 密钥对HSM token 内生成（远程由运维脚本生成，本地由 PKCS#11 GenerateKeyPair）私钥不出 HSM；公钥可公开（远程模式经 /pubkey 获取）包装/解包 DEK 与盲索引密钥
DEK（数据加密密钥）应用内 crypto/rand 生成 32 字节随机值经租户公钥包装后以 wrapped_key 落库（wrap_key_type=dek）敏感字段 AES-256-GCM 加密（enc:v1 信封）
盲索引密钥同上，独立 32 字节随机值同版本独立行落库（wrap_key_type=index）手机号等 HMAC-SHA256 盲索引，支持等值查询
local-master:v1 KEKSHA256("yzws-tenant-crypto:v1:" + JWTSecret) 派生不单独落库；仅兼容适配器内存持有仅解包旧 local-master:v1 记录并迁移，禁止用于新密钥

1.2 提供方模式与选择

模式判定包装（Wrap）解包（Unwrap）健康检查
远程 hsm-sign-servicesofthsm2.server_url 非空（当前 config.yaml 生效模式）应用本地用租户公钥做 RSA PKCS#1 v1.5（公钥公开，无需服务端参与）POST /unwrap + X-Tenant-ID，服务端在 HSM 内用租户私钥解密GET /healthz 期望返回 ok
本地 SoftHSM2（PKCS#11）server_url 为空且配置了 pkcs11_module_env / pin_envtoken 内公钥加密（CKM_RSA_PKCS）token 内私钥解密（私钥 CKA_EXTRACTABLE=false）枚举机制列表确认 CKM_RSA_PKCS 可用
cloud_kmskms_provider=cloud_kms（预留）本版为占位实现，任何调用返回“未接入”错误，业务代码无需修改即可扩展返回未配置
localkms_provider=local 或提供方不可用时的过渡发行仅允许 local-master:v1 引用的包装/解包（AES-256-GCM），生成/轮换一律拒绝包装+解包自检
测试环境 SoftHSM 2.6.1（Botan2 后端）OAEP 解密不可用，故包装算法为 RSA PKCS#1 v1.5（与 hsm-sign-service 服务端一致）； 生产（OpenSSL 后端 / 云 KMS）应切回 RSA-OAEP-SHA256（config.yaml wrap_algorithm 已注明）。

3. 场景详述

3.0 服务启动与 HSM 接入 ✅ 已实现

启动时 main.go 按配置创建 KeyProvider：远程模式校验 hsm-sign-service 可用性；本地模式加载 PKCS#11 模块、定位 token、用 PIN 登录并确认机制可用。 提供方创建失败只告警不回退：涉及密文的读写将返回 KEY_UNAVAILABLE，防止在 HSM 缺席时静默降级。

图 2　服务启动与 HSM 接入时序

3.1 场景一：创建租户（发行密钥） 🔶 部分实现

注册审批通过时需要为该厂建立首版密钥体系：随机 DEK 与盲索引密钥各一把，用该厂 RSA 公钥包装后写入 tenant_crypto_key（同一版本两行：wrap_key_type=dek 与 index）。 远程模式下若该厂尚未在 HSM 开通（/pubkey 返回 404），配置了 ssh_target 时自动经 SSH 执行 add-tenant.sh 开通并轮询生效；未配置则返回 KEY_UNAVAILABLE。

图 3　创建租户（发行密钥）时序
关于 Invalidate：图中“生成随机 DEK + 盲索引密钥”是新发行密钥材料，随后用租户公钥包装落库； 最后一步 Invalidate 只是把该厂内存中已缓存的密钥材料清空（不是替换为 DEK/indexKey，也不改动数据库记录）， 使后续首次加解密时按刚落库的新密钥记录重新从 HSM 解包，避免读到发行前残留的旧缓存。

异常与边界

情况行为
HSM 未开通该租户且未配置 ssh_target返回 KEY_UNAVAILABLE，提示先开通租户密钥；不回退 local 生成新密钥
SSH 自动开通后 25s 内公钥仍不可见报错并提示重启 sign-svc 刷新对象缓存（SoftHSM 新对象对服务端有秒级可见延迟）
提供方为 nil / local 的过渡环境IssueKeys 回退 local-master:v1 包装（与 ensureTenantCryptoKey 同格式），保证未接入 HSM 环境可用；接入 HSM 后按 3.6 轮换迁移
重复审批/重复发行tenant_crypto_key 以 (tenant_id, wrap_key_type, key_version) 唯一约束幂等，EnsureKeys 对已存在 active 密钥直接跳过

3.2 场景二：员工建档（敏感字段加密写入） ✅ 已实现

管理人员/工人建档在 2PC 双写事务内完成：明文库写明文 + phone_hash；密文库同一主键写 enc:v1 密文。 HSM 在事务前用于解包盲索引密钥（手机号查重）与 DEK（字段加密），密钥材料仅存在于内存。

图 4　员工建档（加密写入）时序
读取口径：唯一性、组织层级等校验一律读主库 yzws-v1-sec（api.DB=读池，默认 read_source=secure）； yzws-v1 仅作为双写明文副本，测试期用于对账与核查加密库数据正确性（如比对两库数据、排查异常），日常不作为业务读取来源。
加密列范围（dualwrite.SensitiveColumns）：employee 的 phone、id_card_no、address、birth_date、nation、native_place、bank_card、bank_name、emergency_contact、emergency_phone； tenant / visitor_lead / customer / supplier 的联系方式与地址同理。工号、姓名、组织 ID、状态、phone_hash 等检索/关联字段不加密。

3.3 场景三：员工检索（信息中含加密项的解密） 🔶 部分实现

默认 read_source=secure：人员检索从密文库读出 enc:v1 密文，服务端按信封内密钥版本找到对应 DEK 记录， 经 HSM 解包后做 AES-256-GCM 解密并校验 AAD（租户/表/行/字段/版本绑定，防止密文被复制到他厂或他行），最后按权限脱敏返回。 密钥材料在内存缓存 5 分钟，缓存期内不重复访问 HSM。

图 5　员工检索（加密项解密）时序

异常与边界

情况行为
信封 AAD 校验失败返回 invalid ciphertext envelope：密文被复制到其他租户/行/字段或已损坏，拒绝解密
信封版本无对应密钥记录LoadTenantKey 失败，按 KEY_UNAVAILABLE/内部错误上抛，不做跨版本静默解包
HSM 不可用Unwrap 返回 KEY_UNAVAILABLE；不回退 local 解包新数据（仅 key_wrap_ref=local-master:v1 的旧记录允许 local 解包）
迁移过渡期明文混存非 enc:v1 前缀的值原样透传（兼容历史明文），列表仍执行脱敏
read_source=plain直接读明文库，不调用 HSM；脱敏与权限规则不变

3.4 场景四：手机号登录（盲索引密钥解包） ✅ 已实现

手机号 + 密码登录时，密文手机号无法等值查询：服务端先从 HSM 解包该厂盲索引密钥，计算 HMAC-SHA256 后按 phone_hash 定位账号。 HSM 只参与盲索引密钥解包；口令校验为 Argon2id，不经过 HSM。

图 6　手机号登录（盲索引）时序

3.5 场景五：明文离线备份导出 ✅ 已实现

从密文库读取本厂数据，经 HSM 解包 DEK 逐行解密后写出 JSONL（每行一条完整记录）+ manifest（表名/行数/SHA-256）。 备份包为受控明文例外：不含密钥、会话、票据与各类日志；下载凭证一次性、10 分钟有效，取包即作废；zip 在响应流内打包，不在公开目录落临时文件。

图 7　明文离线备份导出时序
明文备份是受控安全例外：备份包不再受字段级加密保护，等同于明文数据库。权限 backup:export 不随 tenant_admin 身份自动获得； 导出/校验/下载全部写审计，日志不含业务明文；用户应使用受控离线介质保管并自行制定保留与销毁周期。

3.6 场景六：密钥轮换 🔶 部分实现

轮换创建新版本密钥对与新版本 DEK/盲索引密钥，旧版本置 rotated 并保留于 HSM，继续承担历史密文解密； 新写入使用新版本，历史密文可按信封内版本选择旧密钥解密。全部历史数据重加密完成前不得销毁旧私钥。

图 8　密钥轮换时序

3.7 场景七：删除租户 📋 规划/运维流程

删除租户是不可逆操作，设计上按“停用 → 保留期 → 备份确认 → 清库 → 销毁密钥 → 审计”执行。 HSM 侧密钥删除只允许运维脚本在 HSM 内完成（与生成同口径），应用不持有删除接口。

图 9　删除租户（规划）时序

3.8 场景八：数据互转与存量补发（datatool） ✅ 已实现

全量互转（plain→secure / secure→plain）执行前，为缺少密钥记录的存量主体（各租户 + platform）幂等补发密钥； 随后逐表复制：向密文库写时加密、向明文库写时解密，并回填明文库 phone_hash 盲索引。

4. 密钥与数据格式

4.1 tenant_crypto_key 记录（每版本两行）

列说明
tenant_id密钥主体：制衣厂 id 或 platform（平台级，迁移 057 起无外键，应用层保证合法性）
wrap_key_typedek（数据加密密钥）/ index（盲索引密钥）；与 key_version 联合唯一
key_version每厂递增；当前 active 每类型仅一行（部分唯一索引/事务保证）
wrapped_key经租户公钥包装后的密钥材料（Base64），禁止明文入库，禁止返回 API、禁止进入审计快照
key_providerlocal（仅迁移）/ softhsm2 / cloud_kms（预留）
key_wrap_ref解包引用，格式见 4.2
statusactive / rotated / revoked；每类型同时最多一个 active

4.2 key_wrap_ref 格式

提供方格式示例
远程 hsm-sign-servicesofthsm2:<token_label>:<tenantID>:<version>softhsm2:yzws-mes-test:t-abc123:1
本地 PKCS#11softhsm2:<token_label>:<key_label>:<version>（key_label = 前缀 + tenantID + "-v" + 版本）softhsm2:yzws-mes-test:yzws-tenant-t-abc123-v1:1
local（旧数据）local-master:v1local-master:v1
cloud_kms（预留）cloud_kms:<provider>:<key_id>:<version>—

4.3 字段密文信封

enc:v1:<key_version>:<base64url(nonce || ciphertext || tag)>

AAD = tenant_id + 0x1F + table_name + 0x1F + primary_key + 0x1F + column_name + 0x1F + "v1"

NULL 不加密仍存 NULL；空字符串照常加密（与 NULL 区分）。密文不参与排序与模糊查询； 手机号等值查询必须走 phone_hash 盲索引。AAD 绑定租户/表/行/字段/版本，密文复制到他厂、他行或他字段后无法通过认证。

5. 安全与故障处理

主题口径
私钥边界私钥只在 HSM token / hsm-sign-service 内，CKA_EXTRACTABLE=false；数据库、配置、日志、审计均不出现私钥、PIN、API Key、明文 DEK
故障不回退HSM 不可用一律返回 KEY_UNAVAILABLE；不回退 local 解包新数据（仅 local-master:v1 旧记录允许 local 解包）
远程重试最多 3 次指数退避（200ms 起 + 随机抖动）；网络错误 / 5xx / 429 重试，4xx 不重试；多 IP 回退拨号（IPv4 优先）
密钥材料缓存按 租户:类型:版本 缓存 5 分钟；发行/轮换后 Invalidate 该厂缓存；进程退出即失效
自动开通仅远程模式且配置 ssh_target 时：404 → SSH 执行 add-tenant.sh → 轮询公钥（25×1s）；HTTP 服务本身不提供密钥生成/删除接口
过渡发行provider 为 nil/local 时 IssueKeys 回退 local-master:v1，保证未接入 HSM 环境可用；接入后按 3.6 轮换迁移
日志错误信息脱敏截断（≤300 字符）；HTTP 日志不含 SQL 参数；备份/审计不含业务明文与密钥
健康观测远程 GET /healthz；本地机制探测；双库状态 GET /api/v1/system/health/datastore（单写/单库不可达显示 degraded）

6. 配置说明

crypto:
  envelope_version: v1
  data_algorithm: AES-256-GCM
  # 测试环境 SoftHSM 2.6.1（Botan2 后端）OAEP 解密不可用，故为 RSA-PKCS1v15；
  # 生产（OpenSSL 后端 / 云 KMS）切回 RSA-OAEP-SHA256
  wrap_algorithm: RSA-PKCS1v15
  kms_provider: softhsm2          # 测试：softhsm2；预留：cloud_kms；local 仅迁移旧数据
  softhsm2:
    # 远程模式（当前生效）：server_url 非空，无需本机 PKCS#11 库
    server_url: "http://127.0.0.1:8443"     # 也可用 CLOTHP_HSM_SERVER_URL 覆盖
    api_key_env: CLOTHP_HSM_API_KEY          # X-API-Key 只从环境注入
    ca_cert_file: ""                         # HTTPS 自签证书时指向服务端 CA（可选）
    timeout_ms: 10000
    ssh_target: ""                           # 如 root@服务器IP；也可 CLOTHP_HSM_SSH_TARGET
    token_label: yzws-mes-test
    # 本地 PKCS#11 模式备用（server_url 留空时生效，需 Linux + -tags softhsm2 构建）
    # pkcs11_module_env: CLOTHP_SOFTHSM2_MODULE
    # pin_env: CLOTHP_SOFTHSM2_PIN
    # key_label_prefix: yzws-tenant-
环境变量用途
CLOTHP_HSM_SERVER_URL覆盖 hsm-sign-service 地址
CLOTHP_HSM_API_KEY远程调用 X-API-Key
CLOTHP_HSM_SSH_TARGET租户密钥自动开通的 SSH 目标（需免密）
CLOTHP_SOFTHSM2_MODULE / CLOTHP_SOFTHSM2_PIN本地 PKCS#11 模块路径 / token PIN
Windows 开发机使用远程模式：先挂 SSH 隧道（ssh -N -L 8443:127.0.0.1:8443 root@服务器IP）即可，无需本机 SoftHSM2； 本地 PKCS#11 模式仅用于 Linux 测试环境（go build -tags softhsm2，依赖 cgo 与 PKCS#11 模块）。
